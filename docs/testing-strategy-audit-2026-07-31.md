## Representative behavior-first workflow

This is a dry-run against a real regression already owned by
`haxe_c-djl.25`; this audit does not modify or claim to fix its active P0 work.

| Scenario field | Record |
| --- | --- |
| Preconditions/input | Caxecraft's typed JSON decoder returns managed String values through a compiler-generated enum flow carrier; the pinned Haxe/haxe.c/native toolchain is installed. |
| Action | Compile the focused fresh-managed-value String fixture, then run `python3 examples/caxecraft/run_haxe_c_test.py scenario-native-codec`. |
| Observable result | Managed values must remain live through the returned enum and be disposed exactly once after the caller finishes using them. |
| Error/edge behavior | A compiler rejection must remain exact and source-positioned; if compilation succeeds, ASan must report no use-after-free during collector disposal. |
| Product surfaces | `compiler-admitted-slices` and `runtime-memory-lifetime`; the run does not advance ABI or platform qualification. |
| Protected claim | A fresh managed String can cross this bounded enum-return path with correct ownership and lifetime. |

Red-state evidence captured before this audit changed test governance:

- `npm run test:string-runtime` failed at the focused owner with source-positioned
  `HXC1001` for `function-exit:unowned-fresh-managed-enum-value` in
  `Main.copiedAggregateAliasesHold` (25.77s). This is the intended compiler
  boundary, not a setup failure.
- `python3 examples/caxecraft/run_haxe_c_test.py scenario-native-codec`
  crossed the real generated-C boundary and failed under AddressSanitizer with
  a heap-use-after-free in `hxc_string_owner_is_valid` during collector
  disposal (35.35s).
- `python3 examples/caxecraft/run_haxe_c_test.py content-json` passed, keeping
  the neighboring authored JSON behavior distinct from the ownership defect.

The independent behavior oracle is pinned Haxe Eval for the shared Haxe result,
plus a manually authored native harness and ASan for the C lifetime invariant.
None is generated by the failing ownership implementation. The tracer path is:

```text
authored Utf8Decoder Haxe
  -> haxe.c enum/String ownership lowering
  -> generated strict C project
  -> primary native compiler and harness
  -> exact result plus ASan lifetime observer
```

The double lock is therefore present before the fix: the focused String suite
diagnoses the lowering gap, while the Caxecraft codec path retains the real
cross-language/runtime failure. The active Bead must make both green; this
governance task cannot use one as a substitute for the other.

## Distinct high-risk review

This review is separate from implementation because the change controls public
claim evidence.

| Challenge | Finding | Disposition |
| --- | --- | --- |
| Test sensitivity | The new guard must fail for missing surfaces, unknown capability IDs, missing evidence paths, required claim boundaries, unregistered package owners, or incomplete example metadata. | Enforced by `test:fixture-policy` and ten focused governance tests, including nine deliberate in-memory mutations. |
| Oracle independence | Existing examples named oracle paths but did not explain why they were independent. | Added provenance and semantic refresh rules; implementation-generated expected values remain forbidden. |
| Missing negative cases | The audit itself changes no product behavior; adding compiler negatives would manufacture volume. | No product fixture added. Schema/guard failures are the correct lower owner. |
| Mocked boundaries | Hello and Caxecraft retain real haxe.c, strict compiler, native runtime, and applicable sanitizer observers. | No boundary replaced with a mock. |
| Selector omissions | A path-only explanation could hide which claim matrix is affected. | Planner output now attaches product surfaces; unknown ownership falls back to R4. |
| Scorecard laundering | A new scorecard could accidentally become a second capability authority. | Every scorecard references capability IDs and records `doesNotProve`; the bootstrap manifest remains authoritative. |
| Overbroad examples | Calling Caxecraft a flagship could imply every planned path passes. | The case advertises only its full headless domain command and explicitly excludes planned playable/release claims. |
| Release overclaim | Six rings could make R5 look implemented. | R5 has no command and names its blocking E10 owners. |

The first independent `gpt-5.6-sol` xhigh review did not approve the change. It
found that script-name heuristics could contradict scorecard ownership, the
manual guard admitted schema-invalid authority fields and commands, and R4 did
not say when its fallback was required. Those findings were accepted, not
downgraded:

- the planner now loads owner-to-surface and concrete R3 commands directly from
  the checked scorecards;
- the guard rejects undeclared fields, invalid archetypes/status, duplicate
  values, unknown stable Beads owners/capabilities/scripts, malformed evidence
  and selector records, noncanonical backstops, and invalid release commands;
- policy-only owners carry no product surface, while an unknown target path or
  unmapped semantic owner marks R4 `required` with an explicit reason; and
- focused mutations retain the reviewer's adversarial cases, including schema
  authority, command, owner, duplicate-surface, and extra-field failures.

The second independent pass accepted the R3/R4 repair but still rejected two
bypasses: the guard did not yet mirror legacy runner/expected/artifact schema
constraints, and a policy-only or example owner could still contradict the
scorecards. Those findings were also accepted. The final repair validates the
complete case field sets and JSON integer bounds (including the `bool`/integer
distinction), records policy-only package owners in the same scorecard
authority, requires each example to name its package owner, checks its surfaces
exactly against that owner, and treats R3 owners as direct surface owners too.
The pre-existing `contains` stream assertion and inline zero-runtime-plan case
are now represented honestly in the schema instead of being silently outside
it.

A third pass found one remaining policy-only path through `systemOwners`.
Because the selector legitimately consumes package scripts from that field, the
guard now applies the same exclusion there and the mutation test covers both
focused and system owners. The final `gpt-5.6-sol` xhigh review reran that
surviving mutation, reported no findings, and approved the change.

The same reviewer receives the repaired diff before this audit can close.
